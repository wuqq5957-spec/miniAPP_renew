店铺评分规则（一期建议）

一、设计目标

店铺评分用于反映单个门店近期、真实的服务体验，帮助用户进行消费决策。

一期参考大众点评对评价真实性、评价数量、评价时间和评价可信度的处理，但不引入复杂的分项评分及不可解释的榜单算法。规则应同时满足以下目标：

  • 用户容易理解；
  • 产品与研发容易落地；
  • 少量评价不会造成评分剧烈波动；
  • 近期、真实到店的评价拥有更高影响力；
  • 连锁品牌下的不同门店独立计算评分。

1. 评分方式

  • 店铺只计算“整体评分”，不拆分环境、服务、效果等细项。
  • 单次评分最低为 1 分，最高为 5 分。
  • 支持按照 0.5 分递增。
  • 文字评价为选填项，不影响评分提交。
  • 店铺评分，四舍五入保留一位小数，例如 4.8分。
  • 前台同时展示有效评价数量，例如 4.8　300条评价。

2. 哪些评价计入店铺评分

2.1 门店消费订单评价

订单评价需要同时满足以下条件：

  • 评价已发布并审核通过；
  • 服务完成后无论订单是否退款，评价均可正常计入；
  • 每个订单只取第一条审核通过的评价计入评分，后续追评仅展示、不重复计分；

订单评价的来源权重为 1.0。

2.2 会员预约到店后评价

会员预约到店评价需要同时满足以下条件：

  • 用户通过预约到店；
  • 预约已由门店确认到店；
  • 评价已发布并审核通过；
  • 不要求产生付费订单；
  • 每次已完成的预约只取第一条审核通过的评价计入评分，后续追评仅展示、不重复计分；

该行为定义为平台的“到店验证”。到店验证评价的来源权重为 0.7。

2.3 团购活动订单评价 - RTS订单

订单评价需要同时满足以下条件：

  • 评价已发布并审核通过；
  • 服务完成后无论订单是否退款，评价均可正常计入；
  • 每个团购活动订单只取第一条审核通过的评价计入评分，后续追评仅展示、不重复计分；

订单评价的来源权重为 1.0。

2.4 不计入评分的评价

以下评价不计入评分：

  • 审核中或审核失败的评价；
  • 店铺线上商城购买商品评价。
  • 刷评、商家员工自评、虚假到店或其他违规评价；（二期， 此条本期暂不考虑）

3. 店铺评分计算

3.1 评价综合权重

评价综合权重 = 评价来源权重 × 时间权重

评价来源权重：

评价来源来源权重
团购活动订单评价、门店消费订单评价1.0
会员预约评价0.7

时间权重：

评价发布时间时间权重
最近 180 天「T-180， T」1.0
181～365 天「T-365， T-180）0.7
超过 365 天（ T - 发布日期 > 365 个自然日）0.4

示例：

  • 最近 180 天的订单评价：综合权重为 1.0 × 1.0 = 1.0；
  • 最近 180 天的会员预约到店评价：综合权重为 0.7 × 1.0 = 0.7；
  • 超过 365 天的会员预约到店评价：综合权重为 0.7 × 0.4 = 0.28。

3.2 基础分（待确认？ 是否不强制定义基础分， 而是开放运营数据录入入口，由平台运营人工填写数据）

为了降低少量评价造成的评分剧烈波动，一期设置内部基础分：

  • 基础分：4.0 分；
  • 基础样本数：3 条；
  • 基础分只参与内部计算，不作为用户评价展示；
  • 没有足够有效评价时，不能将基础分直接展示为门店评分；
  • 随着真实评价增加，基础分的影响会自然减弱。

3.3 最终计算规则

店铺评分 =〔Σ（每条有效评分 × 该条评价的综合权重）＋基础分 × 基础样本数〕÷〔Σ（所有有效评价的综合权重）＋基础样本数〕

计算结果按照四舍五入保留一位小数。

4. 少量评价处理

为了避免新店凭一两条五星评价直接显示 5.0 分：

有效评价数量前台处理方式
0 条不生成评分，显示“暂无评分”
1～5 条展示评分，同时标注“评价较少”
6条及以上正常展示评分

有效评价数量按通过审核且符合计分资格的评价条数统计，不按照权重折算条数。

5. 重复评价与关联规则

  • 一个订单最多贡献一次评分；
  • 一次已完成的会员预约最多贡献一次评分；
  • 同一用户可以因为多次真实消费或多次真实到店而多次评价；

6. 评分文字对应关系

分数范围评价文字
1.0 分及以下很差
1.5～2.0 分较差
2.5～3.0 分一般
3.5～4.0 分还行
4.5～5.0 分满意

评分文字主要用于用户提交评价后的即时反馈及评价记录展示，不需要与店铺总评分绑定展示。

7. 更新与异常处理

  • 新评价审核通过后，重新计算店铺评分；
  • 评价进入新的时间区间后，其时间权重随下一次定时任务更新；
  • 一期建议每天统一重算一次，新增或删除评价时可以触发即时重算；

计算案例

案例一：新店获得 4 条五星订单评价

条件：

  • 4 条评价均来自已完成订单；
  • 4 条评价均为 5.0 分；
  • 均发布于最近 180 天；
  • 每条评价综合权重均为 1.0；
  • 基础分为 4.0 分，基础样本数为 3 条。

计算过程：

  1. 有效评价加权总分：5.0 × 1.0 × 4 = 20；
  2. 有效评价权重总和：1.0 × 4 = 4；
  3. 基础分贡献：4.0 × 3 = 12；
  4. 店铺评分：（20＋12）÷（4＋3）= 4.57；
  5. 保留一位小数后展示为：4.6 分。

说明：如果不使用基础分，4 条五星评价会直接得到 5.0 分。加入基础分后，可以降低少量评价对新店评分的过度影响。

案例二：订单、预约与直接店铺评价混合计算

某门店共有以下 3 条有效评价：

评分评价来源发布时间来源权重时间权重综合权重评分贡献
5.0已完成订单最近 180 天1.01.01.05.00
4.0会员预约到店最近 180 天0.71.00.72.80
3.5已完成订单200 天前1.00.70.72.45

计算过程：

  1. 有效评价加权总分：5.00＋2.80＋2.45 = 10.25；
  2. 有效评价权重总和：1.0＋0.7＋0.7 = 2.40；
  3. 基础分贡献：4.0 × 3 = 12；
  4. 店铺评分：（10.24＋12）÷（2.40＋3）= 4.1185；
  5. 保留一位小数后展示为：4.1 分。

该门店已有 3 条有效评价，达到评分展示门槛，但评价不足 6 条，因此前台同时标注“评价较少”。

案例三：真实评价增多后基础分影响减弱

某门店已有 30 条最近 180 天的订单评价，真实平均分为 4.6 分：

  1. 有效评价加权总分：4.6 × 30 = 138；
  2. 有效评价权重总和：30；
  3. 基础分贡献：4.0 × 3 = 12；
  4. 店铺评分：（138＋12）÷（30＋3）≈ 4.545；
  5. 保留一位小数后展示为：4.5 分。

当评价数量继续增加时，基础样本数始终只有 3 条，其影响占比会越来越低，评分将逐渐接近真实评价的加权平均分。

一期规则摘要

店铺评分统计审核通过的订单评价、会员预约到店验证评价和团购活动订单评价。订单评价来源权重为 1.0，到店验证评价来源权重为 0.7。评价综合权重由来源权重与时间权重共同决定，并通过 4.0 分、3 条基础样本进行冷启动平滑。没有有效评价时不展示评分，1～5 条时标注“评价较少”，6 条及以上正常展示。

门店主页逻辑说明（一期建议）

适用范围：门店主页及其入口交互。按模块定义数据口径、展示条件、跳转行为与异常处理。

一、门店顶部信息区域

1.1 页面入口与数据范围

  • 用户可从平台门店列表、搜索结果、门店分享链接或二维码进入。每次进入必须携带明确的门店 ID。
  • 门店基础资料、会员资产、活动、人员和评价均按该门店 ID 查询；
  • 未登录也可浏览门店公开内容，不要求用户先授权定位；主页不因缺少定位而无法打开。

1.2 字段与数据来源

  • 门店头图：取门店档案配置的主页封面，按固定容器等比例裁切，不能拉伸；使用底部渐变保证白色名称与评分可读。
  • 门店名称：取门店完整展示名称；位于头图下方区域。名称较长时允许换行，头图文字区随内容适配，不遮挡分享图标。
  • 评分与评价数量：取评价服务返回的汇总数据；评价数量展示该门店公开、审核通过的评价条数
  • 经营分类：取门店经营分类，美发/美甲美睫/美容。
  • 详细地址：取门店档案中的详细地址信息；允许完整换行，不与电话按钮重叠。
  • 营业状态与时间：取门店营业配置及营业状态。- 这个有吗？格式是什么样的？

1.3 门店资料缺省

  • 地址缺失展示“地址待完善”，营业时间缺失展示“营业时间待完善”，不默认判定为营业中。
  • 评分缺省：无有效计分评价时展示“暂无评分”，不展示星星或基础分；1～5 条有效计分评价时同时标注“评价较少”；6 条及以上正常展示评分。具体统计口径见评分规则。

1.4 页面分享

  • 右上角“…”菜单中的分享入口与头图分享图标，均进入微信好友分享流程；不要求登录。
  • 分享标题＝门店完整展示名称；分享卡片＝门店主页公开内容的首屏快照，保留头图、名称等门店信息，不截入会员资产、个人资料、弹窗及遮罩。
  • 分享链接只携带目标门店 ID 等必要路由参数，不携带分享者的身份、定位、会员卡或预约信息。
  • 好友打开卡片进入对应门店主页，重新查询实时数据，并按好友自己的登录状态展示资产。
  • 取消分享返回原页面，保留滚动位置。

1.5 电话入口

  • 点击号码或“呼叫”调用系统拨号能力，号码取所浏览门店的电话配置。
  • 没有有效号码时隐藏电话入口。

1.6 操作：买单、立即预约

  • 买单：进入本门店买单页 （已有功能页面）
  • 写评价：一期不在门店主页展示入口；评价仅从已到店预约或可评价订单入口发起。
  • 立即预约：携带门店 ID 进入发起预约页，由用户选择项目、发型师及可预约时间；未从具体发型师入口进入时，不默认指定人员。门店未开启线上预约功能时，该入口隐藏（已有功能页面）

1.7 登录与返回

  1. 点击买单或预约入口时校验登录态；未登录客户，进入小程序统一登录页。
  2. 登录成功后返回发起登录的门店主页，刷新用户资产及业务权限，保留门店 ID 和可恢复的浏览位置。
  3. 取消或登录失败返回原页面，保持未登录展示。
二、会员资产卡片

2.1 展示条件与查询范围

  • 仅在已登录、且查询到用户在本门店已建档时显示整块卡片。未登录或确认无资产时整块隐藏
  • 资产按登录用户 ID＋门店 ID 查询，以后端返回的可用范围及归属为准，不汇总其他门店余额、卡券或预约。

2.2 固定顺序、数值与跳转

  • 余额：展示本门店可用储值余额合计，带“¥”并保留两位小数；
  • 会员卡：展示可在本门店使用的会员卡张数（含过期/耗尽， 不含退卡）；同一卡 ID 只计一次。点击进入本门店会员卡页，与余额入口去向一致。
  • 优惠券：展示用户已领取、有效且适用本门店的未使用优惠券张数。未到生效时间、已使用及已过期券不计入；点击进入本门店优惠券页。
  • 预约：只展示本门店“待到店”预约数量；已完成、已取消等其他状态不计入。点击进入本门店预约列表，待到店及历史记录均可查看。

2.3 预约气泡与零值

  • 待到店数量大于 0：显示实际数量，在数字右上角展示“待到店”小气泡。
  • 待到店数量为 0：显示“0”和下方“预约”，隐藏气泡；入口保持可点击，不置灰，不隐藏此列。

2.4 刷新与异常

  • 首次进入、登录成功，以及从买单、卡券、预约相关页面返回时，重新查询可能变化的资产数据。
三、热销活动

3.1 候选范围与展示条件

  • 以本店RTS活动的以及异业的其他门店 RTS 活动为查询范围，活动须已上架、处于可购买时间内，且实际服务门店处于可服务状态。
  • 可展示活动总数为 0 时隐藏整块；

3.2 卡片字段

  • 展示活动主图、名称、项目说明、售价、折扣、划线价；团购活动可增加成团人数，异业活动增加服务门店。
  • 折扣按“售价 ÷ 原价 × 10”计算，保留一位小数。
  • 名称最多两行，项目说明最多两行，超出省略；价格和“抢购”始终可见，不能被长文案挤出卡片。

3.3 分类、排序与展开

  • 分类固定顺序为“全部、内购通、拼好美、老带新、会员日”，单选，默认全部。切换分类重新按对应类型查询，不改变门店范围。（二期，一期不存在分类）
  • 排序：按上架时间降序，再按活动 ID 升序，保证顺序稳定。
  • 每个分类默认展示排序后的前 5 项；不足 5 项按实际数量展示。超过 5 项显示“更多活动”，点击展开其余内容，展开后可收起。
  • 展开数据按每批 10 条加载，直到该分类全部返回；未加载完成时保留加载更多入口。
  • 单个分类无结果时，不展示分类筛选

3.4 点击与返回

  • 点击卡片区域或“抢购”均进入对应 RTS 活动详情页
  • 从活动详情返回保留门店、分类和已展开位置，并刷新价格及可售状态；
四、发型师/美甲师/美容师

4.1 范围与展示内容

  • 名称：美发门店 - 发型师 ； 美甲门店 - 美甲师 ； 美容- 美容师 （以下用发型师代替）
  • 查询本门店启用且对用户公开的发型师；不展示已离职人员，休假ok。
  • 每张卡片展示头像、姓名、头衔及预约入口；头像和头衔取员工档案，预约资格取门店预约配置 - 如有。
  • 横向滑动浏览，优先店主，剩下人员 ID 升序作为同序值的兜底规则。
  • 姓名最多两行，职级一行超出省略；未配置职级隐藏该字段，头像缺失使用统一人员默认头像。各卡片高度及按钮基线保持一致。

4.2 预约交互

  1. 用户点击某位发型师“预约”，先校验登录态；未登录按顶部快捷操作的统一登录流程处理。
  2. 已登录时携带门店 ID、发型师 ID 进入发起预约页，默认选中该发型师。
  3. 页面不得只传姓名匹配人员，避免重名误选；

4.3 缺省

  • 人员总数为 0 时隐藏标题、人员列表及对应栏目导航
五、门店评价

5.1 公开范围与计分口径

  • 只展示本门店已发布、审核通过且未被删除的评价；审核中与审核失败的内容仅由用户在“我的评价”查看。
  • 评价服务分别返回展示数量、综合评分及有效计分样本数。已公开但不满足计分周期或去重条件的评价，可以展示，但不得重复计分。
  • 评分公式、基础样本、订单／到店验证／直接门店评价权重及 365 天规则，统一以“概览 → 店铺评分计算规则”为准；

5.2 主页预览

  • 模块标题展示评价总数，卡片上方展示评分汇总；有有效计分样本才展示分数与对应星级。
  • 按发布时间降序展示最近 5 条已发布评价；不足 5 条按实际数量展示，不重复填充。相同发布时间按评价 ID 降序保证稳定顺序。
  • 每条展示用户头像、昵称、发布日期、用户评分星级及评价内容；日期使用发布时的时间，不使用订单时间或最近更新时间。
  • 头像缺失使用默认头像；昵称单行省略，不展示手机号替代昵称；正文允许自然换行与正常换段，不得遮挡日期或评分。
  • 点击「查看全部」进入店铺评价页面
六、页面导航与通用配置交互

6.1 平台首页与门店主页的区别

  • 左上角 Home：返回剑琅美遇平台首页。若从平台列表进入，恢复其城市、分类及可恢复的列表位置；若从分享直接进入，无平台页面历史则打开平台首页默认范围。
  • 门店底部固定“主页／商城／订单”。主页对应本门店主页；商城对应本门店商城；订单对应本门店订单列表，均保留目标门店 ID。

6.2 栏目定位与页面返回

  • 页面滚动至内容区时显示栏目导航，按页面实际展示顺序列出热销活动、发型师、评价；点击定位到对应模块标题，标题不能被固定导航遮挡。
  • 滚动时同步高亮所处栏目。模块因无数据隐藏时，其栏目也隐藏，不出现点击后定位到空白的入口。
  • 子页面采用正常页面跳转，返回时恢复来源门店及浏览位置。

6.3 登录态与内容组合

  • 未登录：保留门店公开内容，隐藏会员资产；买单、预约等需要身份的动作触发统一登录。
  • 已登录无会员资产：仅隐藏资产卡片，不影响活动、团队和评价；0 待到店预约不单独触发隐藏资产卡片。
  • 0 活动、0 人员、0 评价分别按各模块规则处理，可同时出现；不得用一个模块的空结果清空其他模块。
  • 用户退出登录或切换账号后，立即清除旧账号的资产及预约缓存；公开资料可保留，个人数据按新登录态重新请求。

门店会员卡页面逻辑说明（一期建议）

适用范围：从门店主页“会员卡”或“余额”入口进入的当前门店会员卡列表。

一、页面范围与展示口径

2.1 单条评价展示

  • 列表上方展示该门店的公开评价总数，以及“最新发布／最早发布”排序选项；不单独设置“发布时间”标题。

  • 头像缺失时使用统一默认头像；昵称缺失时展示“匿名用户”，不得以手机号代替昵称。
  • 昵称单行超出省略；评价正文自然换行并完整展示，不遮挡日期和评分。
  • 评价内容为空时，仅展示用户、日期和评分，不补充虚构文案。

  • 默认按发布时间降序排列，即“最新发布”；用户可切换为升序，即“最早发布”。
  • 发布时间相同时，以评价 ID 作为稳定排序条件：最新发布时 ID 降序，最早发布时 ID 升序。
  • 切换排序后清空现有分页游标，从第一页重新请求，并将列表滚动到顶部；旧排序的异步结果不得覆盖当前列表。

四、分页、加载与异常

4.1 分页规则

  • 首批及后续每批加载 20 条；使用“发布时间＋评价 ID”作为分页游标，避免新增评价造成重复或遗漏。
  • 滚动接近列表底部时加载下一页；按评价 ID 去重后追加。全部加载完成后不再发起请求。

4.2 加载与失败反馈

  • 首次加载展示列表骨架；加载更多时仅在列表底部展示加载状态，不遮挡已加载内容。
  • 首次请求失败时展示加载失败和重试入口；加载更多失败时保留现有列表，并在底部提供重试，不将失败误判为空数据。

  • 页面重新进入或用户主动刷新时重新查询第一页；已删除或审核状态发生变化的评价，以最新服务端结果为准。

  • 页面不提供跨门店切换；切换门店必须先返回平台首页或进入另一门店主页，再打开对应评价列表。

  • 评分：必填，支持 0.5 分粒度；未选择评分时“提交评价”按钮不可用。
  • 评价内容：选填，最多 500 字；输入时实时显示字数。内容为空时仍可仅提交评分。
  • 点击提交前校验评分、登录态、来源评价资格及表单状态；同一评价在提交处理中不可重复发起。
三、敏感词校验交互
  • 用户点击“提交评价”后，先发起敏感词校验；按钮即时显示“检验中…”，并禁用再次提交与评价内容编辑，避免重复请求或校验内容发生变化。
  • 敏感词校验通过后，按钮切换为“提交中…”，直接进入评价提交流程，无需用户再次点击。
  • 敏感词校验未通过时，保留用户已填写的评分和正文，恢复编辑及提交能力，并显示提示：“您发布的评价中包含敏感词汇，请修改后再提交”。
  • 用户修改正文后清除未通过提示；再次提交时按最新正文重新校验。敏感词规则以服务端词库与审核策略为准，前端不保存或展示命中的具体词汇。
  • 校验服务异常或超时时，不提交评价，恢复按钮并提示“检验失败，请稍后重试”。
四、提交结果与审核
  • 提交成功后创建一条“审核中”的个人评价记录，返回来源页面或“我的评价”；公开门店评价列表仅展示审核通过且已发布的内容。
  • 审核失败时在“我的评价”展示失败状态和原因；审核中及失败内容不进入门店公开评价统计与列表。
  • 当前 Demo 演示“检验中 → 提交中 → 提交成功”流程，不调用真实敏感词服务，也不创建持久化评价记录。
五、技术接入建议（非强制）

以下为技术实现建议，不构成产品功能的供应商强制要求；研发可基于现有基础设施选择同等能力的内容审核服务。

  • 一期可优先评估接入阿里云内容安全 · 文本审核增强版（TextModeration），用于评价正文的敏感内容检测，并配合自定义词库覆盖品牌辱骂、竞品引流、联系方式及营销导流等业务规则。

三、排序与分页
  • 默认按提交时间倒序排列；提交时间相同的记录按评价 ID 倒序排列，保证顺序稳定。
  • 首次加载 20 条；继续下滑时按游标加载下一页。没有更多记录时展示“没有更多评价”。

剑琅美遇·首页 状态演示

可叠加选择状态，再次点击取消；正常状态可一键恢复。

一、范围与规则状态

本文用于确认小程序首页的城市、定位、搜索、活动推荐、门店筛选、排序、分页及卡片展示逻辑。

已确定的核心规则：

  • 首页是平台门店列表，没有“当前门店”的概念；点击门店进入对应店铺详情。
  • 城市选择支持“全国”，全国范围允许查看全部符合展示条件的门店。
  • 只有开启 LBS 定位且成功获得有效定位结果时，才展示门店距离；未授权定位、定位失败、仅有收货地址等情况均不展示距离。
  • 门店优先展示“我的门店”，再优先就近门店；就近排序的参考位置优先使用 LBS，收货地址次之。
  • 分类为：全部、美发、美容、美甲美睫、我的门店；标签单选。
二、左上角城市如何确定

2.1 浏览范围与客户真实定位分开

  • 左上角展示的是“浏览范围”：全国或某个城市，不保证等于用户实际所在城市。
  • 城市弹层中的“当前定位”只表示实际 LBS 定位结果，不能使用历史城市或收货地址冒充。
  • 选择“全国”后，左上角显示“全国”；即使真实位置在上海，也继续保持全国浏览范围。
  • 只使用LBS定位标记用户真实位置， 不以城市中心点、默认门店或历史访问门店作为用户真实位置。

2.2 首次进入及重新打开

  • 用户首次进入小程序时，默认进入“全国”。
  • 用户可主动选择 LBS 定位城市或其他目标城市；选择后，本次访问始终保留该城市，不被自动定位覆盖。
  • 用户下次打开小程序时，恢复上一次主动选择的城市。
  • 若用户从未选择城市，或小程序本地数据被清除（如删除小程序后重新访问），重新默认进入“全国”。

2.3 手动选择、返回和重新定位

  • 本次访问期间，手动选择的全国或城市优先，不被后台定位刷新自动覆盖。
  • 从店铺详情返回首页，保留浏览范围、搜索词、分类、已加载列表和滚动位置。
  • 手动切换浏览城市后，分类恢复“全部”，列表从第一页加载。
  • 点击“重新定位”，成功后切换至实际定位城市，同时更新推荐结果；这是用户主动发起的范围变更。重新定位失败时保留原浏览范围，提示“定位失败，请重试或手动选择城市”。
  • 未授权展示“未开启定位”；
  • 已授权但未取得有效结果展示“暂未获取定位”，提供重试或手动选择入口。

3.1 距离展示条件

同时满足以下条件才显示距离：

  1. 用户已开启 LBS 定位权限。
  2. 本次取得有效定位结果。
  3. 对应门店有有效坐标，能够计算距离。

不满足任一条件，直接隐藏距离字段及分隔符，不显示“0m”“距离未知”或收货地址距离。此规则同时适用于门店列表和推荐活动卡片。

距离使用用户 LBS 到实际门店的直线距离，不是导航路程。全国或跨城市浏览时，只要上述条件满足，也可显示真实距离，不伪造“附近”。

3.2 排序位置与展示距离分开

  • 一次查询统一使用一个参考位置：有效 LBS 优先，其次默认收货地址坐标，最后为无参考位置。
  • 收货地址只使用用户已有的默认地址，不随机选择其他地址；没有可用默认地址时跳过。
  • 不能某家店使用 LBS、另一家使用收货地址混合计算后比较距离。
  • 个别门店缺少坐标时，作为距离不可计算处理，不切换到另一套位置来源。
  • 用户关闭 LBS 后停止使用该定位结果并隐藏距离；若有默认收货地址，仍可辅助排序。

例：用户在上海浏览杭州，门店范围限定杭州。若 LBS 有效，列表可显示用户到杭州门店的真实距离；

四、搜索框

4.1 搜索范围

  • 全国：搜索全国范围内符合展示条件的门店。
  • 指定城市：只搜索该城市内的门店，不自动混入外地结果。
  • 搜索与所选分类同时生效，例如“上海＋美发＋大悦城”。
  • 搜索结果沿用门店列表排序，一期不叠加复杂的搜索相关度权重。

4.2 匹配字段

一期按以下字段进行关键词包含匹配：

  • 门店名称。
  • 详细地址。

支持名称中的部分文字，忽略首尾空格，英文不区分大小写。不匹配价格、评分、活动名称、评价内容；一期不做拼音、错别字纠正或语义搜索。

输入时可做约 300 毫秒防抖；每次有效搜索条件变化，从第一页查询，并避免旧请求结果覆盖新关键词的结果。清空搜索后恢复该浏览范围和分类下的门店列表。

4.3 无结果

  • 文案：“未找到相关门店”。
  • 提供“清空搜索”；指定城市时可增加“查看全国门店”。
  • 用户点击“查看全国门店”才扩大范围，可保留关键词继续查找；不静默扩大搜索范围。

九、典型案例

案例 1：未授权定位，首次访问，没有默认地址

默认进入全国；门店列表不限制城市；不显示任何门店距离。未登录时不使用“我的门店”优先，按可用评分和固定编号排序。

案例 2：未授权定位，有上海默认收货地址

没有历史浏览城市时，建议初始化为上海。门店可按该默认地址就近排序，但卡片不显示距离；

案例 3：已成功定位上海，手动选择全国

左上角展示全国，全国门店均可参与列表筛选；有有效坐标的门店显示到用户的真实距离。我的门店先展示，再在组内按就近排序。

案例 4：已定位上海，手动选择杭州

门店列表只展示杭州门店，有条件时展示真实的跨城距离。

案例 5：浏览过程中关闭定位

门店列表和活动卡片中的距离立即消失，不再使用旧 LBS。若有默认收货地址，改用其辅助排序；否则跳过距离排序。浏览范围保持用户选定的全国或城市，不强制改变。

十、页面分享

10.1 入口与分享内容

  • 平台首页右上角“…”打开分享菜单，选择“分享给微信好友”；右侧关闭小程序按钮与分享入口分开。
  • 分享标题固定为：发现好门店，遇见更美的自己。
  • 以微信小程序卡片形式分享首页链接，点击卡片进入平台首页，不进入某一家门店。
  • 分享封面使用首页公开内容的首屏快照；每次发起分享时重新生成，不截入分享菜单或弹窗。沿用所选全国／城市的公开内容，不含定位距离、搜索历史、会员关系或资产等个人信息。

10.2 好友打开后的行为

  • 好友打开后默认进入平台首页“全国”，按好友自身的登录状态和定位权限展示实时内容。
  • 不传递分享者的登录信息、定位坐标、搜索词、筛选条件或会员身份；快照仅用于预览，不代表好友打开后仍有相同价格、活动或列表顺序。
  • 浏览首页及发起分享不要求登录，不强制开启定位。分享是可选行为，不作为使用其他功能的前置条件。

10.3 取消、异常与 Demo 演示

  • 取消分享或关闭菜单，保留原首页城市、分类及滚动位置，不刷新列表。
  • 快照生成失败时，使用预先准备的首页公开内容默认快照；不得阻断浏览。
  • Demo 流程：“…” → “分享给微信好友” → 查看标题与首页快照卡片 → “模拟发送给微信好友”；不调用微信、不实际发送消息、不声称真实发送成功。
